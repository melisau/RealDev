# First use and learning observations

The initial feedback was: “I do not understand where to start or which goal to choose.” The account page now offers three intentions: find general gaps, prepare for a role, or remain undecided. Each role has a plain-language description. The general Full stack starting route is a suggestion, not a job commitment; no Game development goal is preselected for everyone.

After saving a nickname, goals and daily time, the daily page shows the next concrete step: complete the short scan, try a tested code task, then continue the personal route. An unfinished scan resumes. Intended private pages survive sign-in and profile setup. Users can change goals later.

The state API derives private learning observations from existing account records: completed scan, distinct answered tasks, verified code tasks, and unhinted correct answers following a previous wrong/skipped answer. Counts are descriptive. A repeat is not new breadth, a hint-assisted answer is not independent recovery, and small samples cannot establish learning effectiveness. No third-party analytics or new personal tracking identifiers are added.

Next human usability session: ask a new user to choose a starting intention without help, explain the selected role, complete the first scan, find one review and reach a code task. Record confusion and completion time with consent. Compare delayed performance on a different problem, not only repeated answer accuracy. This release includes the stated feedback; it does not claim a completed population study.

Public learning pages: /learn and /en/learn, with twelve original sourced concepts in each language. Each article is server-rendered without login or SPA scripts, has its own canonical URL and bilingual alternate links. Account pages remain noindex and all private APIs enforce authentication/ownership. noindex is a discovery preference, not an authorization mechanism.
